# Axeptio Android SDK - Version 2.6.0 Release Notes

**Release Date:** September 29, 2026
**Package:** `io.axept.android:android-sdk:2.6.0`

---


### Added

- **listener:** structured AxeptioError payload and one bounded retry of a failed popup load
- **listener:** add onPopupDisplayed callback
- **display:** recover a failed CMP display on network return and from onError

### Changed

- **release:** set VERSION_NAME to 2.5.1 [skip ci]

### Fixed

- **webview:** stop tearing down the CMP on sub-resource load errors
- **analytics:** order popup-close flush after the close event enqueue
- **analytics:** keep the event pipeline alive when a step throws an Error
- **analytics:** order in-app appends and keep unsent events past cap eviction
- **analytics:** remove sent events by queue position, not payload value
- **analytics:** build in-app events after the consent write is durable
- **dialog:** always remove the CMP window on close so the host is never frozen
- **dialog:** never touch the destroyed WebView from a late close read
- **dialog:** stop reserving the navigation bar twice below the CMP popup
- **listener:** report a non-transient failure that arrives during a pending retry
- **a11y:** announce the CMP popup and move TalkBack focus into its content
- **listener:** notify onPopupDisplayed only once content is visible AND presented
- **restore:** keep the silent WebView alive and report only real decisions
- **restore:** bound silent cycles and drop abandoned-cycle events
- **restore:** detach the silent WebView container from its own host
- **restore:** stall-based silent watchdog; end cycles on normal teardown
- **restore:** scope silent errors and reads to their own WebView
- **display:** keep the network-restore latch armed when the re-display is declined
- **display:** arm the restore latch on lost validation and hand off declined restores
